Explore the archive

Use Explore the archive on the dashboard to enter an inclusive interval and see prime counts, checked coverage, and archived primes. You can browse the archive without enrolling a worker.

Run prime ui to open the archive dashboard at the local address printed in your terminal. It reads live data from Atlas. To use the dev archive, run prime --server https://prime-dev-api.notallow.cc ui. With Prime v0.2.0, use this website for the researcher guide and documentation.

Replay the estimates

The Estimates page lets you compare archive counts with five formulas, inspect errors by window width, and download the observations behind each chart. Each dataset identifies its archive revision, model version and zero table.

For an inclusive window [a, b], the count estimate is F(b) − F(a − 1). The weighted observation adds ln(p) for every prime power pᵏ in the window. The model evaluates the zeta explicit formula at b + ½ and a − ½. Sampling between integers avoids the midpoint convention at a prime power.

The numerical implementation uses 50 decimal digits and the first 64 conjugate zero pairs from David Platt’s verified LMFDB table. The heatmap compares mean absolute errors over the fully observed windows at each width. Click a cell to see the individual measurements. The model implementation gives the formulas and pinned zero-table checksum.

Download the prediction manifest and its score to retain a forecast. The replay instructions explain how to reproduce the score at a specific revision. Open the resulting JSON on the Estimates page to inspect each window.

Save a range locally

These requests save the verified primes and coverage summary for integers 2 through 100. They use the public production archive. For dev data, set api to https://prime-dev-api.notallow.cc.

api=https://prime-api.notallow.cc
curl -fsS "$api/api/v1/mining/progress" -o prime-progress.json

Read revision from prime-progress.json, substitute that value below, and run both requests against that revision.

revision=PASTE_REVISION_HERE
curl -fsS "$api/api/v1/primes?lo=2&hi=100&limit=100&revision=$revision" -o prime-2-100.json
curl -fsS "$api/api/v1/summary?lo=2&hi=100&buckets=1&revision=$revision" -o coverage-2-100.json

Keep the JSON files with the API origin, inclusive bounds, and revision in your research notes. In this example, covered is "99" and count is "25". The API uses decimal strings for large integers and counts. Use arbitrary-precision integer types when processing them.

Page through results and sync updates

  • For more primes in the same range, pass next_after as after on the next request. Keep the bounds and revision fixed until next_after is null.
  • For more summary results, pass next_cursor as cursor and keep the bounds, bucket count, and revision fixed until next_cursor is null. Add covered and count per bucket across pages. Confirm that covered integers add up to the interval length before treating the range as complete.
  • To sync a local copy of the contiguous archive later, fetch fresh progress from the same API origin. Read the new verified_through and revision. If the frontier has advanced, fetch from your last fully saved frontier plus one through the new frontier at the new revision. Save those pages alongside your previous files.
